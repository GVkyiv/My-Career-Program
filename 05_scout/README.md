# Job Scout

Мониторинг вакансий из почтовых алертов: разбирает письма, отсеивает мусор,
оценивает оставшееся под профиль кандидата и собирает дайджест с черновиками
cover letter. **Подача — руками.**

## Чего эта штука не делает и почему

Не подаётся сама. Не потому что «не успели», а осознанно:

- **Upwork** прямо запрещает автоматизацию действий в аккаунте. Аккаунт с нуля,
  без отзывов — бан на старте убивает направление целиком. Плюс каждый proposal
  стоит Connects.
- **Ирландские вакансии** уходят в чужие ATS (Workday, Greenhouse, SmartRecruiters)
  с разными формами и CAPTCHA. Массовая шаблонная подача — ровно то, что топит
  кандидатов из-за границы.

Узкое место — не скорость подачи, а фильтрация и качество отклика. Автоматизировано
именно это.

## Установка

Зависимостей нет — только стандартная библиотека Python 3.11+ (проверено на 3.14).

1. **App password для Gmail.** Обычный пароль не подойдёт, нужен app password:
   https://myaccount.google.com/apppasswords (требуется включённая двухфакторка).
2. Скопировать `.env.example` в `.env`, вписать туда app password и, по желанию,
   ключ Claude API (https://console.anthropic.com/settings/keys).
   `.env` в git не попадает.
3. Проверить, что письма-алерты падают в Gmail-лейбл `Job` — имя лейбла задаётся
   в `config.json`, поле `mailbox` (можно указать список лейблов).

Без `ANTHROPIC_API_KEY` скрипт работает, но остаётся только предфильтр по
ключевым словам — оценки и черновики писем не собираются.

## Использование

```bash
py -m scout run --drafts 3   # всё сразу: почта → оценка → дайджест
py -m scout fetch            # только забрать письма
py -m scout score            # только оценить неоценённое
py -m scout digest           # только собрать дайджест
py -m scout draft <id>       # черновик письма под конкретную вакансию
py -m scout mark <id> applied
py -m scout status
```

Дайджест ложится в `data/digests/YYYY-MM-DD.md`.

## Запуск по расписанию

`run_daily.ps1` делает полный прогон и открывает готовый дайджест. Повесить на
Планировщик задач Windows: действие `powershell.exe`, аргументы
`-ExecutionPolicy Bypass -File "<путь>\05_scout\run_daily.ps1"`. Лог — `data/run.log`.

## Как это устроено

| Модуль | Отвечает за |
|---|---|
| `scout/mail.py` | Gmail IMAP: забор писем из лейблов за `lookback_days` |
| `scout/parse.py` | разбор письма-алерта на отдельные вакансии |
| `scout/store.py` | SQLite: `data/jobs.db`, дедупликация, статусы |
| `scout/score.py` | предфильтр по ключевым словам + оценка моделью + cover letter |
| `scout/digest.py` | markdown-дайджест |

**Дедупликация** идёт по хешу «заголовок + компания + локация», а не по URL:
ссылки в письмах IrishJobs персонализированные и различаются между письмами.

**Два слоя фильтрации.** Сначала дешёвый предфильтр (`config.json` → `prefilter`):
`hard_exclude` даёт 0 баллов, отсутствие любого слова из `must_match_any` — 15.
До модели такие вакансии не доходят, токены не тратятся. Обратная сторона: слишком
узкий `must_match_any` молча съест что-то живое — список стоит перечитывать,
если дайджесты подозрительно пустые.

**Скоринг** сверяет вакансию с `00_profile/candidate.md` и `01_markets/ireland.md`
(поле `profile_files`). Черновики писем собираются под дисциплину verified-facts-only
из `01_process.md`: модели прямо запрещено вводить цифры и достижения, которых нет
в профиле — вместо них ставится маркер `[НУЖНЫ ДАННЫЕ: ...]`.

## Что ещё не сделано

- Парсер написан и проверен на письмах **IrishJobs**. Для LinkedIn и jobs.ie
  заведены префиксы ссылок, но на реальных письмах они не проверялись — до первой
  проверки такие письма попадут в список «не распознано» при `fetch`.
- Upwork не подключён: нужны saved searches с email-уведомлениями и отдельный
  парсер под их формат писем.
